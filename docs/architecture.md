# Архітектура застосунку

## Загальна схема

```text
Клієнт (HTTP)
     │
     ▼
FastAPI (app/main.py)
     │
     ├── RequestContextMiddleware → журналювання запитів
     ├── Обробники помилок → єдиний формат відповіді
     │
     ▼
API v1 (app/api)
     │
     ▼
Бізнес-модулі (app/modules)
     │
     ▼
SQLAlchemy → PostgreSQL
```

## Модулі системи

| Модуль | Відповідальність | Стан |
|---|---|---|
| `auth` | реєстрація, вхід, ролі користувачів | заплановано |
| `customers` | база клієнтів, контактні дані | реалізовано |
| `products` | каталог товарів і послуг | заплановано |
| `orders` | замовлення, статуси, історія | заплановано |
| `analytics` | звіти та показники | заплановано |
| `notifications` | повідомлення клієнтам | заплановано |

## Шари застосунку

1. `app/api` — приймає HTTP-запити та повертає відповіді.
2. `app/modules/<name>/router.py` — маршрути модуля.
3. `app/modules/<name>/service.py` — бізнес-правила.
4. `app/modules/<name>/repository.py` — доступ до даних.
5. `app/modules/<name>/models.py` — ORM-моделі.
6. `app/modules/<name>/schemas.py` — схеми валідації.

## Логування

Кожен запит отримує ідентифікатор `X-Request-ID`. Middleware фіксує метод, шлях,
код відповіді та тривалість обробки. Формат журналу:

```text
2026-11-18 20:15:03 | INFO     | app.request | POST /api/v1/customers -> 201 (18.4 ms) request_id=6f1c...
```

## Обробка помилок

Усі помилки повертаються в єдиному форматі:

```json
{
  "error": {
    "code": "not_found",
    "message": "Клієнта з ідентифікатором 999 не знайдено",
    "request_id": "6f1c..."
  }
}
```

| Код | HTTP-статус | Причина |
|---|---|---|
| `validation_error` | 422 | некоректні вхідні дані |
| `not_found` | 404 | ресурс відсутній |
| `conflict` | 409 | дублювання унікального поля |
| `internal_error` | 500 | непередбачена помилка |
