# Журнал змін

Усі помітні зміни проєкту документуються в цьому файлі.

Формат — [Keep a Changelog](https://keepachangelog.com/uk/1.1.0/),
версіонування — [Semantic Versioning](https://semver.org/lang/uk/).

## [1.0.0] – 2026-11-21

Перший публічний реліз CRM System. Реліз охоплює реалізований обсяг —
модуль обліку клієнтів і службові маршрути API.

### Додано

- REST API обліку клієнтів: створення, перелік і отримання за
  ідентифікатором (`/api/v1/customers`).
- Перевірка стану сервісу та з’єднання з базою даних
  (`/api/v1/health`).
- Централізована обробка помилок із єдиним форматом `code`, `message`,
  `request_id`.
- Наскрізне логування запитів із заголовком `X-Request-ID`.
- Автоматична OpenAPI-документація (`/docs`, `/openapi.json`).
- Набір із 8 тестів pytest із покриттям 97% і порогом 80%.
- Колекція Postman із 10 запитів і 44 assertions на ітерацію для
  функціональної та регресійної перевірки API.
- CI-пайплайн GitHub Actions: Ruff, pytest, інтеграція з PostgreSQL 16,
  Newman і збірка Docker-образу.
- CD-пайплайн: публікація Docker-образу в GitHub Container Registry за
  тегом `v*`.
- Документація: `README.md`, `docs/architecture.md`, `docs/ci-cd.md`,
  `docs/deployment.md`, `docs/support.md`, `postman/README.md`.
- Інструкція з розгортання для адміністраторів у трьох режимах:
  Docker Compose, опублікований образ GHCR і локальний запуск.
- План підтримки та оновлень: канали зворотного зв’язку, класифікація
  дефектів, процес виправлення, версіонування, регресійне тестування й
  моніторинг.

### Змінено

- Версію застосунку, `pyproject.toml` і метадані OpenAPI приведено до
  `1.0.0`.
- `README.md` актуалізовано для кінцевих користувачів та адміністраторів:
  додано розділи про реліз, розгортання, підтримку й обмеження.
- Docker-образ для релізу публікується з тегами `1.0.0`, `latest` і
  `sha-<commit>`.

### Обмеження

- Реалізовано лише модуль `customers`; модулі `auth`, `products`,
  `orders`, `analytics` і `notifications` заплановані та відстежуються в
  GitHub Issues.
- Немає автентифікації й авторизації, тому API не призначений для
  відкритого доступу з інтернету без додаткового захисту.
- Перелік клієнтів повертається без пагінації; операції `PATCH` і
  `DELETE` не реалізовані.
- Схема бази створюється через `create_all`; контрольовані міграції
  Alembic заплановані на наступний реліз.

### Безпека

- У релізі 1.0.0 відсутня автентифікація. Розгортання слід виконувати в
  закритому контурі, за VPN або за зворотним проксі з автентифікацією.
- Пароль PostgreSQL у прикладах є тестовим; для робочого середовища його
  потрібно замінити та зберігати поза репозиторієм.

## [0.1.0] – 2026-11-18

Початкова версія каркасу CRM System: структура застосунку, конфігурація,
логування, централізована обробка помилок, модуль `health`, модуль
`customers`, Docker Compose для PostgreSQL 16 і перші тести pytest.
